## Consolidated patient email migration

The current Hostinger `patients.email` has a global unique index. The new migration adds and verifies `UNIQUE(clinic_id,email)` before removing only exact single-column global email unique indexes. It refuses invalid clinic ownership, existing per-clinic duplicates or conflicting index definitions; it never rewrites patient rows. Null emails remain optional; the database collation remains authoritative. DDL is nontransactional and may briefly lock the table; inspect postconditions and keep a fresh recovery checkpoint. `down()` deliberately refuses: valid cross-clinic equal emails must never be removed or forced into global uniqueness. Old source preserves the data but may reject cross-clinic shared-email registrations until fixed forward. No production execution occurred.

No customer dump is regenerated from the business database for this development change. There is no tracked schema dump in this isolated release tree; canonical migrations and the source-derived synthetic fixtures remain the schema authority.
